2. Simple Linear Regression — OLS 1 feature · closed form
In 30 seconds

Fit ŷ = mx + c by minimising squared error. Setting the derivatives to zero gives m = Σ(x−x̄)(y−ȳ)/Σ(x−x̄)² and c = ȳ − m x̄, so the line always passes through (x̄, ȳ).

The Model

ŷ = mx + c

x = input, ŷ = predicted output, m = slope, c = intercept. Infinitely many (m,c) pairs are possible — we need an objective criterion to pick the best one.

Why Squared Error Wins

Loss attemptFormulaProblem
1. Signed ErrorΣ(yᵢ−ŷᵢ)Positive/negative errors cancel — can be 0 even with huge individual errors
2. Absolute ErrorΣ|yᵢ−ŷᵢ|Not differentiable at e=0 (sharp V corner) — blocks clean calculus. Robust to outliers though (linear penalty).
3. Squared Error Σ(yᵢ−ŷᵢ)²Always non-negative, smooth & differentiable everywhere, penalizes large errors quadratically → sensitive to outliers, but this is the OLS choice.
Outlier sensitivity: error 1→penalty 1, error 10→penalty 100 (squared) vs penalty 10 (absolute). A 10× larger error gets 100× the squared penalty — this is why OLS lines get pulled toward outliers.

Full Derivation — Step by Step

Goal: find the (m, c) that minimizes the total squared error over all n data points. Define the error function (this is a function of two variables, m and c — x and y are just the fixed data):

E(m,c) = Σᵢ₌₁ⁿ (yᵢ − mxᵢ − c)²

Since E is a smooth bowl-shaped (convex) function of m and c, its minimum occurs exactly where both partial derivatives are zero. This gives us two equations in two unknowns (m, c) — solve them together.

Step 1 — Solve for c
Step 2 — Solve for m

Set ∂E/∂c = 0. Differentiate the sum term-by-term (the sum and derivative can be swapped since it's a finite sum). Using the chain rule on (yᵢ−mxᵢ−c)², the outer power rule gives a factor of 2 and the inner derivative w.r.t. c is −1:

∂E/∂c = Σᵢ 2(yᵢ−mxᵢ−c)·(−1) = −2Σᵢ(yᵢ−mxᵢ−c)

Set this equal to 0 and divide both sides by −2:

Σᵢ(yᵢ−mxᵢ−c) = 0

Split the sum into three separate sums (linearity of summation):

Σᵢyᵢ − mΣᵢxᵢ − Σᵢc = 0

The last term is c added to itself n times (c does not depend on i), so Σᵢc = n·c. Substitute and rearrange for c:

Σᵢyᵢ − mΣᵢxᵢ = n·c  ⟹  c = Σᵢyᵢ/n − m·(Σᵢxᵢ/n)

But Σᵢyᵢ/n is exactly the definition of the mean ȳ, and Σᵢxᵢ/n is the mean x̄. So:

c = ȳ − m·x̄
Geometric meaning: this single equation says the fitted line ŷ=mx+c must satisfy ȳ = m·x̄ + c — i.e. the point (x̄, ȳ) always lies exactly on the OLS line, no matter what m turns out to be. That's why "the regression line passes through the mean" is always true.

Set ∂E/∂m = 0. Same chain rule, but now the inner derivative w.r.t. m is −xᵢ:

∂E/∂m = Σᵢ 2(yᵢ−mxᵢ−c)·(−xᵢ) = −2Σᵢxᵢ(yᵢ−mxᵢ−c) = 0

Divide by −2 and substitute c = ȳ − m·x̄ from Step 1 (this is why we solve for c first):

Σᵢxᵢ(yᵢ − mxᵢ − ȳ + m·x̄) = 0

Group the y-terms and the m-terms separately:

Σᵢxᵢ(yᵢ − ȳ) − mΣᵢxᵢ(xᵢ − x̄) = 0

Now use a small algebraic trick: Σᵢxᵢ(yᵢ−ȳ) is equal to Σᵢ(xᵢ−x̄)(yᵢ−ȳ), because expanding Σᵢx̄(yᵢ−ȳ) = x̄Σᵢ(yᵢ−ȳ) = x̄·0 = 0 (deviations from the mean always sum to zero). The same trick turns Σᵢxᵢ(xᵢ−x̄) into Σᵢ(xᵢ−x̄)². So the equation becomes purely in terms of deviations:

Σᵢ(xᵢ−x̄)(yᵢ−ȳ) − mΣᵢ(xᵢ−x̄)² = 0

Finally, solve for m:

m = Σᵢ(xᵢ−x̄)(yᵢ−ȳ) / Σᵢ(xᵢ−x̄)²
Key insight: the OLS best-fit line always passes through (x̄, ȳ) — the mean of the data. Numerator = covariance of x,y; denominator = variance of x. If every x is identical, denominator = 0 → slope undefined.
Why solve c first? Because ∂E/∂m=0 alone has two unknowns (m and c). Substituting the c-equation collapses it down to one equation in one unknown (m), which we can then solve directly. This "solve one, substitute into the other" pattern reappears in every OLS-style derivation in this course.

def find_mean(values):
    return np.mean(values)

def find_slope_intercept(x, y, x_mean, y_mean):
    numerator   = np.sum((x - x_mean) * (y - y_mean))
    denominator = np.sum((x - x_mean) ** 2)
    if denominator == 0:
        raise ValueError("Cannot calculate slope: x has zero variance.")
    m = numerator / denominator
    b = y_mean - m * x_mean
    return m, b

def predict_lr(x, m, b):
    return m * x + b

def r_square(y, y_pred, y_mean):
    ss_total    = np.sum((y - y_mean) ** 2)
    ss_residual = np.sum((y - y_pred) ** 2)
    return 1 - (ss_residual / ss_total)

3. Multiple Linear Regression — OLS Matrix form · Normal Equation
In 30 seconds

With many features, ŷ = Xβ and OLS gives the normal equation β = (XᵀX)⁻¹Xᵀy. It fails when XᵀX is singular (perfect multicollinearity). Matrix facts (transpose, inverse, symmetric) are explained inside.

The Model & Matrix Form

ŷ = β₀ + β₁x₁ + β₂x₂ + ... + βₘxₘ = Xβ

X is the design matrix (n × (m+1), first column all 1's for the intercept), β is the parameter vector ((m+1) × 1), ŷ is n × 1. This is a hyperplane in m dimensions — still linear in the parameters.

Matrix Properties You Need First

The whole MLR derivation is just calculus, but done with vectors/matrices instead of scalars. Four facts make it work — learn these once and reuse them everywhere below and in Batch GD:

Property 1

Transpose of a product

(AB)ᵀ = BᵀAᵀ — the order flips. For three or more: (ABC)ᵀ = CᵀBᵀAᵀ.

Property 2

Transpose of a scalar

If z is a 1×1 matrix (a plain number), zᵀ = z. A scalar equals its own transpose — always. This is the trick that merges two "different-looking" terms into one.

Property 3

Symmetric matrix

A matrix A is symmetric if Aᵀ = A. Claim: XᵀX is always symmetric, for any X. Proof: (XᵀX)ᵀ = Xᵀ(Xᵀ)ᵀ = XᵀX (using Property 1, and (Xᵀ)ᵀ=X). Since (XᵀX)ᵀ = XᵀX, it is symmetric.

Property 4

Why symmetry matters

The identity ∂(βᵀAβ)/∂β = 2Aβ only holds when A is symmetric (otherwise it's (A+Aᵀ)β). Since A=XᵀX is always symmetric (Property 3), we're always safe to use the "×2" version.

Full Derivation — Step by Step

Step 1 — Write the loss. Let e = y − Xβ be the vector of residuals (n×1). The total squared error is the sum of eᵢ², which for a vector is exactly the dot product of e with itself, eᵀe:

L(β) = eᵀe = (y−Xβ)ᵀ(y−Xβ)

Step 2 — Expand the product. Distribute the transpose over the subtraction using Property 1: (y−Xβ)ᵀ = yᵀ − (Xβ)ᵀ = yᵀ − βᵀXᵀ. Now multiply out:

L(β) = (yᵀ − βᵀXᵀ)(y − Xβ) = yᵀy − yᵀXβ − βᵀXᵀy + βᵀXᵀXβ

Step 3 — Merge the two middle terms. Look closely: yᵀXβ is a 1×1 scalar (row · matrix · column). By Property 2, a scalar equals its own transpose, so yᵀXβ = (yᵀXβ)ᵀ = βᵀXᵀ(yᵀ)ᵀ = βᵀXᵀy. That means the two middle terms are actually equal to each other, not just similar — so they combine:

L(β) = yᵀy − 2βᵀXᵀy + βᵀXᵀXβ

(written with βᵀXᵀy instead of yᵀXβ — same value, just the conventional form used before differentiating)

Step 4 — Differentiate term by term w.r.t. the vector β. Three matrix-calculus identities are needed, and here is why each one is true:

Identity 1

∂(constant)/∂β = 0

yᵀy contains no β at all — it's just a fixed number once the data is fixed. The derivative of a constant is always 0, exactly like scalar calculus.

Identity 2

∂(aᵀβ)/∂β = a

aᵀβ = a₁β₁+a₂β₂+...+aₖβₖ is linear in each βⱼ. Differentiating w.r.t. βⱼ picks out aⱼ alone (every other term has zero derivative), so stacking all partials back into a vector gives exactly a. Here a = Xᵀy.

Identity 3

∂(βᵀAβ)/∂β = 2Aβ (A symmetric)

βᵀAβ = ΣᵢΣⱼ Aᵢⱼβᵢβⱼ is quadratic in β. Differentiating w.r.t. one βₖ, by the product rule every term containing βₖ contributes — this works out to (Aβ)ₖ + (Aᵀβ)ₖ. When A is symmetric, Aᵀ=A, so this is 2(Aβ)ₖ. Stack over all k → 2Aβ. Here A = XᵀX, symmetric by Property 3.

Tiny worked check (Identity 3, 2×2 case): let A = [[a,b],[b,d]] (symmetric: off-diagonals equal) and β=[β₁,β₂]ᵀ. Then βᵀAβ = aβ₁² + 2bβ₁β₂ + dβ₂². ∂/∂β₁ = 2aβ₁+2bβ₂, ∂/∂β₂ = 2bβ₁+2dβ₂. Stacked: [2aβ₁+2bβ₂, 2bβ₁+2dβ₂]ᵀ = 2Aβ — matches the identity exactly.

Step 5 — Apply the three identities to L(β) = yᵀy − 2βᵀXᵀy + βᵀXᵀXβ term by term (a=Xᵀy for the middle term, A=XᵀX for the last):

∇L = 0 − 2Xᵀy + 2XᵀXβ

Step 6 — Set gradient to zero (this is the vector equivalent of ∂E/∂m=0, ∂E/∂c=0 from SLR — a minimum requires every partial derivative to vanish simultaneously):

−2Xᵀy + 2XᵀXβ = 0  ⟹  XᵀXβ = Xᵀy  (the Normal Equation)

Step 7 — Solve for β. If XᵀX is invertible, left-multiply both sides by (XᵀX)⁻¹:

β* = (XᵀX)⁻¹ Xᵀy
Compare to SLR: notice XᵀXβ=Xᵀy is exactly the matrix version of the two scalar equations we solved by hand in SLR (Σyᵢ=mΣxᵢ+nc and Σxᵢyᵢ=mΣxᵢ²+cΣxᵢ — the "normal equations" of SLR). MLR just packages the same two-equation system into one matrix equation that works for any number of features.
Multicollinearity: if any column of X is a linear combination of others, XᵀX is singular → det(XᵀX)=0 → (XᵀX)⁻¹ doesn't exist. OLS formula breaks.
Computational cost: inverting a k×k matrix costs O(k³). For m=100,000 features, that's 10¹⁵ operations ≈ 11.6 days — impractical. Use Gradient Descent instead for large m.

# Build design matrix and solve the Normal Equation manually
def fit_multiple_lr(X, y):
    ones = np.ones((len(X), 1))
    H = np.hstack((ones, X))              # design matrix with intercept column
    beta = np.linalg.inv(H.T @ H) @ H.T @ y   # β = (XᵀX)⁻¹Xᵀy
    return beta

def predict_multiple_lr(X, beta):
    ones = np.ones((len(X), 1))
    H = np.hstack((ones, X))
    return H @ beta

4. Batch Gradient Descent Iterative optimization
In 30 seconds

When no closed form is used, descend the loss: θ ← θ − α∇J, using all n rows for one update per epoch. Too large α diverges, too small crawls; scaling features helps.

Why Not Always OLS?

  • Cost: inverting XᵀX is O(m³) — impractical for large m.
  • Invertibility: requires XᵀX non-singular (no multicollinearity).

Gradient Descent avoids inverting XᵀX entirely — it iteratively walks downhill on the loss surface.

The Update Rule

θnew = θold − α∇L(θold)

α = learning rate (hyperparameter). The gradient points in the direction of steepest increase; the negative gradient points downhill.

Full Derivation — Deriving ∇L from MSE

This reuses exactly the same matrix properties and identities as the MLR Normal-Equation derivation above (transpose of a product, transpose of a scalar, symmetric matrices, and the three matrix-calculus identities) — the only difference is we stop at the gradient instead of setting it to zero and solving in closed form.

Step 1 — Write the Mean Squared Error loss for m training examples, using θ in place of β (same idea, different variable name for iterative methods):

L(θ) = (1/m)(y−Xθ)ᵀ(y−Xθ)

Step 2 — Expand exactly as before (transpose over subtraction, then merge the two equal scalar cross-terms using "transpose of a scalar = itself"):

L(θ) = (1/m)[ yᵀy − 2θᵀXᵀy + θᵀXᵀXθ ]

Step 3 — Differentiate term by term using the same three identities (∂const/∂θ=0, ∂(aᵀθ)/∂θ=a with a=Xᵀy, ∂(θᵀAθ)/∂θ=2Aθ with A=XᵀX, symmetric):

∇L = (1/m)[ 0 − 2Xᵀy + 2XᵀXθ ] = (2/m)[ XᵀXθ − Xᵀy ] = (2/m) Xᵀ(Xθ−y)
Normal Equation vs Gradient Descent: in the Normal Equation we set this exact expression to 0 and solved for θ in one shot: XᵀXθ=Xᵀy → θ*=(XᵀX)⁻¹Xᵀy. In Gradient Descent we don't solve it — we just evaluate ∇L at the current θ and take a small step opposite to it, repeating many times. Same math, two different uses.

Substituting into the update rule gives the final rule used in code and numericals:

θ := θ − α·(2/m)Xᵀ(Xθ−y)
Simultaneous update: ALL partial derivatives must be computed using the OLD θ, and ALL parameters updated together. Never use an updated θ₀ to compute the gradient for θ₁ in the same step.

Learning Rate Effects

αEffect
Too smallConverges, but painfully slowly
Too largeOvershoots, may oscillate or diverge
Well chosenFast initial drop, flattens near minimum

Training Loop

  1. Initialize θ = 0 (convex loss)
  2. Predict: ŷ = Xθ
  3. Residual: Xθ − y
  4. Gradient: ∇L = (2/m)Xᵀ(Xθ−y)
  5. Update: θ := θ − α∇L
  6. Repeat for chosen epochs / until convergence
Feature scaling matters here too: unscaled features (e.g. attendance 60-90 vs hours 2-6) make the gradient wildly larger in one dimension, distorting convergence. Always scale before Gradient Descent.

Code — Batch Gradient Descent (Lab 5)

Python
def predict_mlr(X, weights):
    ones = np.ones((len(X), 1))
    H = np.hstack((ones, X))
    return H @ weights

def compute_mlr_gradient(X, residual):
    ones = np.ones((len(X), 1))
    H = np.hstack((ones, X))
    return (2/len(X)) * (H.T @ residual)

def batch_gradient_descent_mlr(X, y, weights, alpha, epochs):
    loss_history = []
    for i in range(epochs):
        predictions = predict_mlr(X, weights)
        residual    = predictions - y
        gradient    = compute_mlr_gradient(X, residual)
        weights     = weights - alpha * gradient          # simultaneous update
        loss = np.mean(residual ** 2)
        loss_history.append(loss)
    return weights, loss_history

y = β₀ + β₁x + β₂x² + ... + βₙxⁿ

Multicollinearity Deep-Dive

If X₁ and X₂ are highly correlated, individual coefficient estimates β₁, β₂ become unstable/unreliable (can even flip sign). Perfect multicollinearity (X₁ = a·X₂ exactly) makes XᵀX singular → (XᵀX)⁻¹ doesn't exist.

Trap: x and x² are correlated by construction, but BOTH may be needed to capture curvature — don't blindly drop one just because of high pairwise correlation.

8. Bias, Variance & the Tradeoff Y = f(x) + ε
In 30 seconds

High bias = underfit (train and test both bad). High variance = overfit (train good, test bad). Fix bias with a richer model; fix variance with more data, regularization or a simpler model.

Setup

Y = f(X) + ε,   E(ε)=0,   Var(ε)=σ²

f(X) = true hidden function (unknown), fˆ(x) = our estimator — a random variable because it depends on which random training sample we happened to draw.

Definitions

Bias(fˆ(x)) = E[fˆ(x)] − f(x)
Variance(fˆ(x)) = E[(fˆ(x) − E[fˆ(x)])²]
MSE = Bias² + Variance + Var(ε)    (Reducible + Irreducible Error)

Underfitting vs Overfitting

Too simple

High Bias, Low Variance → Underfits

e.g. a straight line for y=x² data. Models trained on different samples end up very similar to each other, but all fail to capture the curve.

Too complex

Low Bias, High Variance → Overfits

e.g. degree-20 polynomial. Fits its own training sample closely but wildly different models emerge from different samples — memorizes noise.

Just right

Low Bias, Low Variance → Good fit

The sweet spot minimizing total error.

Dartboard Analogy

PatternCharacterization
Tight cluster around bullseyeLow Bias, Low Variance
Tight cluster, far from bullseyeHigh Bias, Low Variance
Spread widely around bullseyeLow Bias, High Variance
Spread widely, far from bullseyeHigh Bias, High Variance

Practical Diagnosis (since true f(x) is never known)

SymptomDiagnosis
Train Acc=70%, Val Acc=68% (both low)High Bias (Underfitting)
Train Acc=99%, Val Acc=82% (big gap)High Variance (Overfitting)
Train Acc=98%, Val Acc=97% (both high, small gap)Good fit
Common trap: "99% train, 98% val = high variance because training accuracy is high" — WRONG. It's the small GAP that signals good fit, not the absolute training number.
Learning curves: High Bias → both train & val error stay high even with more data. High Variance → train error low, val error high, but val error DROPS as more data is added.

10. Principal Component Analysis (PCA) Lecture 11 · Lab 11 · Eigen-decomposition
In 30 seconds

PCA finds orthogonal directions of maximum variance: standardise → covariance → eigenvectors → keep top-k → project. EVR = λᵢ/Σλ. It is unsupervised and must be fitted on train only.

Why Dimensionality Reduction? (start here if you know nothing)

A dataset with p features puts every row at a point in p-dimensional space. More features is not automatically better: many columns are redundant (bedroom area and washroom area both just say "big house"), others are noise, and the cost of fitting grows fast. Dimensionality reduction squeezes p columns into k < p columns while keeping as much useful information as possible.

Idea

Feature Selection

Keep a subset of the original columns, throw the rest away. Axes stay the same. (Lecture 10 / your Section 9.)

Idea

Feature Extraction (PCA)

Build brand-new columns that are combinations of the old ones: PC₁ = w₁x₁ + w₂x₂ + … Axes are rotated to line up with the direction of maximum spread.

Definition

What is PCA?

Principal Component Analysis = an unsupervised, linear feature-extraction method that finds new orthogonal axes (principal components) along which the variance of the data is maximised. It never looks at the target y.

Picture it: a diagonal cloud of points (bedroom area vs washroom area, both rising together). Neither original axis follows the cloud. PCA rotates the axes so PC₁ runs along the long diagonal (captures ~96% of the spread, call it "overall house size") and PC₂ is perpendicular (the small leftover "contrast"). Keep only PC₁ → 2 features became 1 with almost no information loss.

Step 1 — Centering (and when to standardize)

Xc = X − 1μᵀ     zij = (xij − μj) / sj  (standardization)
  • Centering only when features share comparable units and their raw variances are meaningful.
  • Standardize (divide by std) when features have different units/scales (rupees vs years) — otherwise the biggest-scale column dominates the covariance matrix and hence PC₁.
  • After standardizing, every feature has variance 1, so the total variance = p (number of features).

Step 2 — Covariance: how two features move together

Cov(x, y) = (1/(n−1)) Σ (xᵢ − x̄)(yᵢ − ȳ)
SignMeaningExample
Positive (+)above-average x tends to come with above-average ystudy hours ↑ ⇒ test score ↑
Negative (−)above-average x comes with below-average yprice ↑ ⇒ units sold ↓
≈ 0no linear co-movementsymmetric U-shape (y = x²) — but they are still dependent!
Zero covariance ≠ independence. y = x² is perfectly determined by x yet Cov(x,y) = 0 (symmetry cancels). Covariance only sees linear relationships. Also: covariance depends on units and is not bounded; correlation = covariance ÷ (std₁·std₂) lies in [−1, +1].

The covariance matrix for 3 features f₁, f₂, f₃:

f₁f₂f₃
f₁Var(f₁)Cov(f₁,f₂)Cov(f₁,f₃)
f₂Cov(f₂,f₁)Var(f₂)Cov(f₂,f₃)
f₃Cov(f₃,f₁)Cov(f₃,f₂)Var(f₃)

Diagonal = variances. Off-diagonal = covariances. It is symmetric (Sjk = Skj). Its trace (sum of diagonal) = total variance = sum of eigenvalues.

Step 3 — Eigenvectors and eigenvalues (the heart of PCA)

S v = λ v   ⟺   |S − λI| = 0

Multiply a general vector by a matrix and it usually rotates and stretches. An eigenvector v is a special non-zero direction that the matrix does not rotate — it only scales it, by the factor λ (the eigenvalue). For PCA the matrix is the covariance matrix S:

  • Eigenvectors of S = the principal directions (the new axes).
  • Eigenvalue λj = the variance of the data when projected onto vj. Bigger λ = more information on that axis.
  • Because S is symmetric, its eigenvectors are orthogonal ⇒ principal components are uncorrelated.
  • Sort eigenvalues in descending order: PC₁ ↔ largest λ, PC₂ ↔ second largest, …

Step 4 — Project onto a direction

For a unit vector u (‖u‖ = 1) the coordinate (score) of a centered observation xi along u is just a dot product:

zi = uᵀ xi     projected point = zi · u     residual ei = xi − ziu
Why this works: the projection of x onto u is (uᵀx / ‖u‖²) u. When ‖u‖ = 1 the denominator is 1, so the length along u is exactly uᵀx. Also ‖x‖² = z² + ‖e‖² (Pythagoras) and ‖x‖ is fixed, so maximising the variance of z is the same as minimising the reconstruction error ‖e‖². That is the whole optimisation PCA solves — and its answer is "take the top eigenvectors of S".

The Complete PCA Recipe

  1. Split data into train / test first. Test set stays locked.
  2. Fit centering (and scaling if needed) on the training set only; store μ and s.
  3. Covariance S = XcᵀXc/(n−1) from centered training data (p × p).
  4. Eigen-decomposition: solve S vj = λj vj.
  5. Sort eigenpairs by descending eigenvalue.
  6. Choose k (explained variance / elbow / visualisation / cross-validation).
  7. Form Wk = [v₁ … vk] (p × k).
  8. Transform: Ztrain = Xc,trainWk, and Ztest = (Xtest − μtrain)Wk — never refit on test.
Leakage rule: never fit the scaler or PCA on the full dataset and then cross-validate. Fit them inside each fold on that fold's training part only (use an sklearn Pipeline).

Choosing k — Explained Variance Ratio (EVR)

total variance = Σλj = trace(S)    EVR(PCj) = λj / Σλ    cumulative EVR(k) = (λ₁+…+λk) / Σλ
  • Cumulative threshold: smallest k reaching 90% or 95% variance, then validate.
  • Scree / elbow: plot eigenvalues; keep components before the curve flattens.
  • Visualisation: k = 2 or 3.
  • Prediction task: treat k as a hyperparameter and tune with cross-validation (variance ≠ predictive power).

Ridge Regression (L2)

LRidge = Σᵢ (yᵢ − mxᵢ − c)² + λ m²

Option check from the lecture: to stop the optimiser choosing large coefficients, add a penalty proportional to the squared coefficients (subtracting them would encourage large values; multiplying by the feature count does nothing about magnitude).

Ridge: full derivation
Lasso: why exact zeros?

Step 1 — ∂L/∂c = 0 (the penalty has no c, so this is identical to OLS):

−2 Σ(yᵢ − mxᵢ − c) = 0 ⟹ c = ȳ − m·x̄

Step 2 — substitute c to remove the intercept. Then yᵢ − mxᵢ − c = (yᵢ − ȳ) − m(xᵢ − x̄), so the loss depends only on m:

L(m) = Σ [(yᵢ − ȳ) − m(xᵢ − x̄)]² + λ m²

Step 3 — differentiate w.r.t. m (chain rule on the square, plus d/dm of λm² = 2λm), set to 0:

−2 Σ (xᵢ − x̄)[(yᵢ − ȳ) − m(xᵢ − x̄)] + 2λm = 0

Divide by 2 and expand the bracket:

−Σ(xᵢ−x̄)(yᵢ−ȳ) + m Σ(xᵢ−x̄)² + λm = 0

Group the m terms and solve:

m ( Σ(xᵢ−x̄)² + λ ) = Σ(xᵢ−x̄)(yᵢ−ȳ)  ⟹  mRidge = Σ(xᵢ−x̄)(yᵢ−ȳ) / ( Σ(xᵢ−x̄)² + λ )
Read the formula: λ sits in the denominator. λ = 0 gives back OLS. Larger λ makes the denominator bigger so m shrinks — but a finite number divided by a finite number is never exactly 0, so Ridge never produces exact zeros.
LLasso = Σᵢ (yᵢ − mxᵢ − c)² + λ |m|

|m| has a sharp "V" kink at m = 0 and is not differentiable there, so analyse it piecewise (the OLS part is unchanged; only the penalty derivative differs):

Case m > 0: |m| = m, penalty derivative = +λ ⟹

m = ( OLS numerator − λ ) / denominator

Case m < 0: |m| = −m, penalty derivative = −λ ⟹

m = ( OLS numerator + λ ) / denominator

λ enters the numerator as a direct subtraction. Once λ ≥ |OLS numerator| the formula would give a value with the wrong sign (violating the case assumption), so the algorithm clips m to exactly 0. Example: numerator 100 — λ=50 ⟹ numerator 50 (m > 0 ); λ=100 ⟹ 0; λ=120 ⟹ negative, assumption broken ⟹ clip to m = 0.

The course writes the Lasso slope as (numerator − λ)/denominator. If you differentiate carefully with the loss exactly as written you get λ/2 (the exact constant depends on how the penalty is scaled), but for the exam use the lecture form: λ in the numerator ⇒ exact zeros; λ in the denominator ⇒ never zero.
Optimisation note: Ridge has a closed form (one matrix computation). Lasso has no closed form — it needs iterative numerical optimisation (e.g. coordinate descent) because of the non-differentiable kink at 0.

Multiple Ridge (N features) and why it fixes multicollinearity

βOLS = (XᵀX)⁻¹ Xᵀy      βRidge = (XᵀX + λI)⁻¹ Xᵀy

Adding λI to XᵀX makes the matrix invertible for every λ > 0, even when XᵀX is singular (perfectly collinear features). Reason: XᵀX is symmetric with eigenvalues ≥ 0 (zero for the collinear directions); adding λI adds λ to every eigenvalue, so all become ≥ λ > 0 ⟹ the determinant (product of eigenvalues) is non-zero ⟹ invertible. So Ridge handles multicollinearity gracefully. (The derivation of this normal equation is out of scope; just remember the formula.)

Six properties of Ridge to memorise

1

Never exactly zero

λ in denominator ⇒ coefficients shrink asymptotically (10⁻⁵…) but stay non-zero. Ridge keeps ALL features.

2

Asymmetric shrinkage

penalty is λw² so big coefficients are punished far more: w=5000 → 25,000,000λ, w=1000 → 1,000,000λ, w=1 → 1λ.

3

Bias–variance

as λ ↑: variance ↓ a lot, bias ↑ a little (up to a point). λ=0: low bias/high variance; λ→∞: high bias/low variance.

4

Loss shifts

the loss parabola's vertex slides from the OLS value toward m = 0 (e.g. 27 → 16 → 6) and the parabola narrows.

5

Name "Ridge"

hard-constraint view: minimise OLS subject to Σw² ≤ r² — a circle. The solution lies on the boundary ("ridge") of the circle.

6

Needs N ≥ 2

most useful with several (possibly correlated) features; with one feature it rarely helps.

Practical rules (very testable)

  1. Split first, then compute μⱼ and σⱼ on the training set only.
  2. Standardize features: xⱼ,std = (xⱼ − μⱼ)/σⱼ. The penalty acts on raw coefficient size, so a feature in rupees (small coefficient) would be unfairly crushed vs one in years. Skipping standardization is the classic reason Lasso wrongly zeros an important feature (e.g. Rainfall).
  3. Select λ by cross-validation over a grid, using λmin (lowest validation error) or λ1SE (simplest model within 1 SE).
  4. Do not regularise the intercept — penalising it pulls predictions toward 0 instead of ȳ. (The sum in the penalty starts at j = 1.)
  5. Bigger λ is NOT always better — too big ⟹ underfitting.

Ridge from scratch with gradient descent (2-parameter)
def fit_ridge_2d(X, y, alpha=1.0, lr=0.001, epochs=5000):
    x = X.flatten()
    m, b = 0.0, 0.0
    n = len(x)
    for _ in range(epochs):
        y_pred = m * x + b
        loss = np.sum((y_pred - y) ** 2) + alpha * m ** 2   # b NOT penalised
        error = y_pred - y
        dm = 2 * np.sum(error * x) + 2 * alpha * m          # penalty adds 2*alpha*m
        db = 2 * np.sum(error)                              # no penalty term for b
        m = m - lr * dm
        b = b - lr * db
    return m, b

m, b = fit_ridge_2d(X, y, alpha=0.1, lr=0.001, epochs=10000)

12. Time Series Analysis Lecture 13 · Lab 13 · Stationarity · AR · MA
In 30 seconds

Time-ordered data is not i.i.d.: split chronologically, make the series stationary (difference), read PACF → p (AR) and ACF → q (MA). MA uses past errors, not a rolling mean.

Why time is special

Everything so far (linear regression, regularization…) assumed rows are I.I.D. — independent and identically distributed. Shuffle the 500 house listings and nothing changes. A time series breaks this: today's value depends on yesterday's, so row order is information. Shuffle daily stock prices and you get meaningless noise.

Data leakage in time series: a random split could train on 2026 data to predict 2024, breaking the arrow of time. Always split by time: e.g. first 80% of days = train, last 20% = test, no shuffling.

(3) A repeating pattern in the residuals means the model FAILED to capture some structure (e.g. seasonality).

A stationary series has statistical properties that do not change over time:

Why it matters: ML models are pattern-matching engines. Most classical models (AR, MA) need stationary data; real data usually isn't, so we transform it first.

A time series has only one column — its own past. Treating lags as feature columns turns forecasting into ordinary supervised regression: predict yt from yt−1, yt−2, …. In pandas: series.shift(k) creates the lag-k column; the first k rows become NaN and are dropped.

Making a series stationary: Differencing

ΔYt = Yt − Yt−1

Instead of absolute values, model the change from one step to the next. This removes the trend (first-order differencing); the differenced series hovers around a constant mean. It loses the first observation (no previous day). Misconception: first-order differencing does not remove seasonality — that needs seasonal differencing (subtract the value from the same season last cycle, e.g. Yt − Yt−7). "Looks stationary" is not proof — a formal test like ADF is needed.

13. MLE & Logistic Regression Lecture 14 · Lab 14 · Sigmoid · Likelihood · BCE
In 30 seconds

Logistic regression squashes a linear score with the sigmoid to get P(y=1). Fitting = maximum likelihood; the negative average log-likelihood is binary cross-entropy.

From regression to classification

Linear regression predicts a number (price, marks). Classification predicts a category (spam / not spam, pass / fail). If we simply fit a straight line to 0/1 labels, the output can be −3 or 7.5, which is meaningless as a probability, and a few outliers drag the line and shift the threshold. We want a model whose output is always between 0 and 1. That model is Logistic Regression, and the principle used to fit it is Maximum Likelihood Estimation (MLE).

Despite its name, logistic regression is a classification algorithm. "Regression" is in the name because it regresses a linear score z, which is then squashed into a probability.

MLE in one line: choose the parameters that make the data we actually observed most probable. Training = searching for the parameters with the highest likelihood.

MLE worked on a coin (the simplest case)

Let θ = P(heads). Data: 7 heads, 3 tails. Likelihood: L(θ) = θ⁷(1−θ)³.

The peak is at θ = 0.7 = 7/10 — the observed fraction of heads. Using calculus on the log: ln L = 7 ln θ + 3 ln(1−θ); d/dθ = 7/θ − 3/(1−θ) = 0 ⟹ 7(1−θ) = 3θ ⟹ θ̂ = 7/10.

Logistic model: step by step

  1. Linear score (like linear regression): z = β₀ + β₁x₁ + … + βdxd = xᵀβ. z can be any real number.
  2. Squash with the sigmoid so the output lies in (0, 1): p̂ = σ(z) = 1 / (1 + e−z).
  3. Interpret p̂ as P(y = 1 | x). Classify as 1 if p̂ ≥ 0.5 (threshold can be changed).

Decision boundary: p̂ ≥ 0.5 ⟺ σ(z) ≥ 0.5 ⟺ z ≥ 0 ⟺ xᵀβ ≥ 0. So the boundary is the straight line/plane β₀ + β₁x₁ + … = 0: logistic regression is a linear classifier even though the probability curve is S-shaped. Step function (hard 0/1, not differentiable) vs sigmoid (smooth, differentiable, gives a probability) — sigmoid is what makes gradient descent possible.

Odds and log-odds (why "logistic")

odds = p / (1 − p)   →   log-odds (logit) = ln( p / (1 − p) ) = z = xᵀβ

The model assumes the log-odds are linear in the features. If z = 0 then p = 0.5 and odds = 1. Each +1 in xj adds βj to the log-odds, i.e. multiplies the odds by eβj. Example: p = 0.8 ⟹ odds = 0.8/0.2 = 4 ⟹ log-odds = ln 4 ≈ 1.386.

The Bernoulli likelihood of one sample

For a single sample with true label y ∈ {0,1} and predicted p̂ = P(y=1|x):

q = P(y | x) = p̂y · (1 − p̂)1−y

If y = 1 this equals p̂ (the exponent 1−y = 0 kills the second factor); if y = 0 it equals 1 − p̂. So q is "the probability the model assigned to the correct label". A good model makes q close to 1 for every sample.

Likelihood → Log-likelihood → Loss (full derivation)

  1. Dataset likelihood (samples independent ⟹ multiply): L(β) = ∏ᵢ p̂ᵢyᵢ(1−p̂ᵢ)1−yᵢ.
  2. Why take log? A product of hundreds of numbers below 1 underflows to ~0, and products are hard to differentiate. log turns the product into a sum and is monotonic, so the maximizer is unchanged.
  3. Log-likelihood: ℓ(β) = Σᵢ [ yᵢ ln p̂ᵢ + (1−yᵢ) ln(1−p̂ᵢ) ].
  4. Turn max into min: optimizers minimize, so use the negative, averaged over n: J(β) = −(1/n) Σᵢ [ yᵢ ln p̂ᵢ + (1−yᵢ) ln(1−p̂ᵢ) ] — the Binary Cross-Entropy (BCE) / log loss.
  5. Maximizing likelihood ≡ minimizing BCE. Linear regression’s MSE is the MLE under Gaussian noise; BCE is the MLE under Bernoulli labels.
Why not use MSE for logistic regression? With the sigmoid inside, MSE becomes non-convex (many flat regions, vanishing gradients). BCE is convex in β, so gradient descent reaches the global minimum. But there is no closed-form solution (unlike OLS), so we must use gradient descent / Newton-type methods.

14. GD on Logistic Regression & Multiclass Lecture 15-16 · Lab 14 · Gradient · OVR · Softmax
In 30 seconds

The BCE gradient is beautifully simple: ∇J = Xᵀ(p̂ − y)/n. For K classes use one-vs-rest (K independent models) or softmax with categorical cross-entropy.

The goal

Logistic regression has no closed-form solution, so we minimize the BCE loss J(β) with gradient descent: repeatedly step β in the direction that decreases J. You already know the recipe from Batch GD: β ← β − α · ∇J(β). All we need is the gradient of BCE.

Gradient derivation (chain rule, step by step)

Work with one sample i. Let z = xᵀβ, p̂ = σ(z), loss Lᵢ = −[ y ln p̂ + (1−y) ln(1−p̂) ].

  1. Loss w.r.t. p̂: ∂L/∂p̂ = −[ y/p̂ − (1−y)/(1−p̂) ] = (p̂ − y) / ( p̂(1−p̂) ).
  2. Sigmoid derivative: σ′(z) = σ(z)(1−σ(z)), so ∂p̂/∂z = p̂(1−p̂).
  3. Linear part: ∂z/∂βⱼ = xⱼ.
  4. Chain rule: ∂L/∂βⱼ = (∂L/∂p̂)(∂p̂/∂z)(∂z/∂βⱼ) = (p̂−y)/(p̂(1−p̂)) · p̂(1−p̂) · xⱼ = (p̂ − y) xⱼ. The ugly p̂(1−p̂) terms cancel!
  5. Average over n samples: ∂J/∂βⱼ = (1/n) Σᵢ (p̂ᵢ − yᵢ) xᵢⱼ.
This has exactly the same form as the linear regression gradient: (prediction − truth) × input. Only the prediction changes: p̂ = σ(xᵀβ) instead of xᵀβ.

Algorithm

  1. Add intercept column; initialise β = 0 (or small random).
  2. Repeat for a number of epochs:
  3. compute z = Xβ, p̂ = σ(z).
  4. compute gradient g = Xᵀ(p̂ − y)/n.
  5. β ← β − αg; optionally record the BCE loss.
  6. Stop after max epochs or when the loss change is tiny. Loss should decrease every epoch; if it rises or oscillates α is too large.
Everything from Lecture 5/6 carries over: batch (all n rows), SGD (1 row), mini-batch (k rows); feature scaling speeds convergence; learning-rate too small = slow, too large = diverge. And since BCE is convex, GD reaches the global minimum.

Non-linear boundaries and regularization

Adding polynomial features (x₁², x₁x₂, …) lets logistic regression draw curved boundaries (still linear in the new features). Too many features overfit, so add an L2 penalty: J = BCE + (λ/2n)·Σⱼ βⱼ² (intercept excluded). In sklearn the regularization strength is C = 1/λ: small C ⟹ strong regularization.

import numpy as np

def gd_linear(X, y, lr=0.01, epochs=1000, batch_size=None):
    """y_hat = w*x + b. batch_size=None -> batch GD, 1 -> SGD, k -> mini-batch."""
    X = np.array(X, float); y = np.array(y, float)
    n = len(X); w = b = 0.0
    bs = n if batch_size is None else batch_size
    for _ in range(epochs):
        idx = np.random.permutation(n)                 # shuffle each epoch
        for s in range(0, n, bs):
            g = idx[s:s + bs]
            err = (w * X[g] + b) - y[g]                # y_hat - y
            dw = (2 / len(g)) * np.sum(err * X[g])     # dJ/dw  (MSE)
            db = (2 / len(g)) * np.sum(err)            # dJ/db
            w, b = w - lr * dw, b - lr * db            # simultaneous update
    return w, b

import numpy as np

def gd_mlr(X, y, lr=0.01, epochs=20000):
    """Multiple regression with matrix gradient: grad = (2/n) H^T (H beta - y)."""
    H = np.hstack([np.ones((X.shape[0], 1)), X])        # add intercept column
    beta = np.zeros(H.shape[1])
    n = len(y)
    for _ in range(epochs):
        grad = (2 / n) * H.T @ (H @ beta - y)           # all coefficients at once
        beta = beta - lr * grad
    return beta

PCA with explained variance (pure NumPy)

Pure NumPy PCA with explained variance ratio
import numpy as np

def pca_scratch(X, k, standardize=True):
    Xc = X - X.mean(axis=0)                             # center
    if standardize:
        Xc = Xc / X.std(axis=0)                         # z-score; StandardScaler uses ddof=0 (population std)
    cov = (Xc.T @ Xc) / (len(Xc) - 1)                   # covariance by formula  S = Xc^T Xc / (n-1)
    vals, vecs = np.linalg.eigh(cov)
    order = np.argsort(vals)[::-1]
    vals, vecs = vals[order], vecs[:, order]
    Z = Xc @ vecs[:, :k]
    evr = vals / vals.sum()                             # explained variance ratio
    return Z, evr[:k], np.cumsum(evr)[:k]

import numpy as np

def ridge_closed_form(X, y, lam):
    H = np.hstack([np.ones((len(X), 1)), X])
    I = np.eye(H.shape[1]); I[0, 0] = 0              # do NOT penalise the intercept
    return np.linalg.inv(H.T @ H + lam * I) @ H.T @ y   # (X^T X + lambda I)^-1 X^T y

def ridge_gd_step(x, y, m, b, alpha, lr):
    n = len(x)
    err = (m * x + b) - y
    dm = (2 / n) * np.sum(err * x) + 2 * alpha * m    # + derivative of alpha*m^2
    db = (2 / n) * np.sum(err)                        # intercept: no penalty
    return m - lr * dm, b - lr * db

def pca(data, k):
    scaled = StandardScaler().fit_transform(data)      # 1. standardise (mean 0, std 1)

def sgd(X, Y, lr, epochs):

    np.random.seed(42)                        # seed ONCE here (see note below)

        idx = np.arange(len(X))               # [0, 1, ..., N-1]

        for i in idx:                         # ONE sample at a time

            dw = 2 * (pred - Y[i]) * X[i]     # gradient of this single sample
            w = w - lr * dw                   # update IMMEDIATELY (N updates / epoch)

def fit_multiple_lr_beta(X, y):
    X = np.array(X, dtype=float); y = np.array(y, dtype=float)
    ones = np.ones((X.shape[0], 1))
    Xp = np.hstack([ones, X])            # 1. prepend a column of 1s  -> intercept beta_0

    return beta

def batch_gd(X, Y, lr, epochs):

            grad_sum += 2 * (pred - Y[i]) * X[i]   # grad_i = 2 (pred - y) x
        dw = grad_sum / n                     # AVERAGE of the N gradients

    return round(w, 2)

def pca(X, k):
    Xc = X - X.mean(axis=0)                 # 1. center (standardize first if scales differ)
    cov = np.cov(Xc, rowvar=False)          # 2. covariance matrix (d x d)
    vals, vecs = np.linalg.eigh(cov)        # 3. eigen-decomposition (ascending order)
    order = np.argsort(vals)[::-1]          # 4. sort descending
    vals, vecs = vals[order], vecs[:, order]
    W = vecs[:, :k]                         # 5. top-k eigenvectors (columns)
    Z = Xc @ W                              # 6. project: z = U^T x
    evr = vals / vals.sum()                 # explained variance ratio
    return Z, evr[:k]
Common mistakes: forgetting to center; using rowvar=True (default!) so features are treated as rows; forgetting to sort eigenvalues (eigh returns ascending); taking rows instead of columns of vecs. Cumulative EVR = np.cumsum(evr).

def ridge_step(x, y, m, b, alpha, lr):

    error = (m * x + b) - y

Rapid-Fire Conceptual Definitions

  • PCA: unsupervised projection onto orthogonal directions of maximum variance (eigenvectors of the covariance matrix); eigenvalue = variance captured.
  • Ridge vs Lasso: L2 shrinks all weights smoothly; L1 sets some to exactly 0.
  • Stationarity: constant mean, variance and autocovariance; fix a trend by differencing.
  • PACF vs ACF: PACF → p (AR); ACF → q (MA).
  • MA model: regresses on past forecast errors, not a rolling average.
  • Likelihood: plausibility of parameters given fixed data; MLE maximizes it; BCE = negative average log-likelihood.
  • Decision boundary (logistic): xᵀβ = 0, a linear boundary.
  • OVR vs softmax: K independent binary models vs one jointly-normalized model.
  • Data Leakage: using validation/test information during training/feature-selection/preprocessing → falsely optimistic scores.
  • Multicollinearity: features linearly dependent → XᵀX singular → OLS coefficients unstable/impossible; harmless for pure prediction, bad for inference.
  • Overfitting: low bias, high variance — fits training noise, fails to generalize.
  • Underfitting: high bias, low variance — too simple to capture the pattern.
  • Homoscedasticity: constant residual spread across all predicted values (assumption 3 of LR).
  • Learning rate too high: overshoot/diverge. Too low: painfully slow convergence.
  • Baseline model: the simplest possible predictor (mean/majority) — new models must justify their added complexity by beating it meaningfully.
  • Filter vs Wrapper (feature selection): Filter = fast statistical screen, no model training. Wrapper = trains the real model on subsets, uses CV score.
  • Model Drift: real-world change makes a deployed model's accuracy decay over time → triggers retraining.
  • Parameters vs Hyperparameters: parameters learned automatically (weights); hyperparameters set manually before training (learning rate, batch size, max_depth).

Solved Numerical 1 — Full Eigen-Decomposition by Hand

Q. The covariance matrix of two features is S = [[4, 2],[2, 4]]. Find the principal components and the explained variance ratio of PC₁.

Step 1 — characteristic equation |S − λI| = 0:
(4 − λ)(4 − λ) − (2)(2) = 0  ⟹  λ² − 8λ + 12 = 0  ⟹  (λ − 6)(λ − 2) = 0  ⟹  λ₁ = 6, λ₂ = 2.

Step 2 — eigenvector for λ₁ = 6: (S − 6I)v = 0 ⟹ [[−2, 2],[2, −2]]v = 0 ⟹ −2v₁ + 2v₂ = 0 ⟹ v₁ = v₂. Normalise to length 1: v₁ = (1/√2)[1, 1]ᵀ.
Eigenvector for λ₂ = 2: (S − 2I)v = 0 ⟹ [[2, 2],[2, 2]]v = 0 ⟹ v₁ = −v₂ ⟹ v₂ = (1/√2)[1, −1]ᵀ. (v₁·v₂ = ½ − ½ = 0 ✓ orthogonal.)

Step 3 — checks: trace(S) = 4 + 4 = 8 = λ₁ + λ₂ = 6 + 2 ✓. det(S) = 16 − 4 = 12 = λ₁·λ₂ = 6·2 ✓.
Step 4 — EVR: PC₁ = 6/8 = 0.75 (75%), PC₂ = 2/8 = 25%. Keep PC₁ → 75% of the variance retained.
Two exam shortcuts for a 2×2: λ₁ + λ₂ = trace(S) and λ₁·λ₂ = det(S). If S = [[a, b],[b, a]] (equal diagonals) the eigenvectors are always [1,1]/√2 and [1,−1]/√2 with eigenvalues a + b and a − b.
