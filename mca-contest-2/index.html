0. The basics you need first

Background for beginners

The whole syllabus in plain language, with worked examples, practice and a quiz. The exam is written: see the contest format and mock paper. Sections tagged in yellow are not from your uploaded lectures.

The five words used everywhere

WordMeaning
InstructionOne small command to the CPU, such as "add two numbers"
RegisterA tiny, very fast storage box inside the CPU ($t0, $t1 …)
Memory (RAM)Big storage outside the CPU core. Much slower than registers
Clock cycleOne "tick" of the CPU. 2 GHz = 2 billion ticks per second, so 1 tick = 0.5 ns
PCProgram Counter: the address of the instruction to fetch. Each MIPS instruction is 4 bytes, so normally PC + 4

How to read MIPS

add $t0, $t1, $t2    # t0 = t1 + t2      (first register is the RESULT)
sub $t0, $t1, $t2    # t0 = t1 - t2
lw  $t0, 8($t1)      # LOAD:  t0 = memory[t1 + 8]

1. Pipelining and the 5-stage MIPS pipeline

Not from your uploaded lectures: standard MIPS material
In simple wordsDo not wait for one job to finish completely before starting the next. Split the work into steps and let different jobs be in different steps at the same time.

Single-cycle CPU and its problem

In a single-cycle CPU, every instruction finishes in one long clock cycle. The cycle must be long enough for the slowest instruction (usually lw), so fast instructions waste time. Most hardware also sits idle while one part works.

Laundry analogy

Four loads, each needing wash, dry, fold and put away, 30 minutes per step.

  • One load at a time: 4 × 2 h = 8 h.
  • Pipelined (start washing the next load when the washer is free): 2 h for the first + 3 × 30 min = 3.5 h.

One load still takes 2 hours. You just finish loads more often.

The five stages

StageFull nameWhat happensFor lw $t0, 8($t1)
IFInstruction FetchRead the instruction at PC; PC + 4Fetch the lw
IDInstruction DecodeWork out the instruction, read registersRead $t1
EXExecuteALU calculates$t1 + 8
MEMMemory accessLoad or store uses data memoryRead that address
WBWrite BackPut the result in a registerWrite $t0

Pipeline registers IF/ID, ID/EX, EX/MEM and MEM/WB sit between stages. They hold each instruction's values and control signals so the next stage can use them, while the earlier stage starts on a new instruction.

Latency, throughput and speedup

  • Latency: time for one instruction from start to finish.
  • Throughput: instructions finished per unit time. Pipelining improves this.
  • Pipelined clock period = slowest stage (plus register delay, if the question gives one).
  • Ideal speedup = number of stages, only if stages are equal, with no hazards and many instructions.

Example: stages take 200, 100, 200, 200, 100 ps.

  • Single-cycle period = 800 ps. Pipelined period = 200 ps.
  • 3 instructions: 2400 ps against 7 × 200 = 1400 ps.
  • Very many instructions: speedup → 800 / 200 = 4, not 5, because stages are unequal.
  • Pipelined latency is 5 × 200 = 1000 ps, which is worse than 800 ps.

Hazards preview

A hazard is anything that stops the next instruction from running in the next cycle. There are three kinds: structural, data and control (next two sections).

2. Data hazards and forwarding

Not from your uploaded lectures: standard MIPS material (the activity at the end is from Lec 16)
In simple wordsAn instruction needs a result that an earlier instruction has not saved yet. Usually we pass the value directly across the pipeline instead of waiting.

Three kinds of hazard

HazardCauseTypical fix
StructuralTwo instructions need the same hardware at once, e.g. one memory for both fetch and dataMore hardware (separate instruction and data memory)
DataNeeds data that is not readyForwarding, stalls, reordering
ControlDoes not yet know which instruction comes next (branch)Stall, predict, flush
DependencyMeaningExample order
RAW (read after write)Later one reads what the earlier one writeswrite $t0, then read $t0
WAR (write after read)Later one writes what the earlier one readsread $t0, then write $t0
WAW (write after write)Both write the same registerwrite $t0, then write $t0

Why only RAW matters here: in this in-order 5-stage pipeline, all instructions read early (ID) and write late (WB), in program order. So a later write cannot overtake an earlier read or write.

Forwarding (bypassing)

The ALU result of add exists at the end of EX. Send it from a pipeline register straight to the ALU input of the next instruction. For the pair above: 0 stalls.

ForwardA / ForwardBALU input comes fromUsed when the producer is
00Register file value (ID/EX)No forwarding needed
10EX/MEM register1 instruction ahead
01MEM/WB register2 instructions ahead

ForwardA is the first ALU input (rs). ForwardB is the second (rt).

EX hazard:  EX/MEM.RegWrite and EX/MEM.Rd != 0 and EX/MEM.Rd == ID/EX.Rs  -> ForwardA = 10
MEM hazard: MEM/WB.RegWrite and MEM/WB.Rd != 0 and MEM/WB.Rd == ID/EX.Rs  -> ForwardA = 01
(Same checks with Rt for ForwardB. If both match, EX/MEM wins: it is newer.
 Rd here means the destination register.)

The load-use hazard

lw gets its data only at the end of MEM. The very next instruction needs it at the start of its EX, which is the same cycle. Forwarding cannot go back in time, so we need 1 stall + forwarding.

Action: freeze PC and IF/ID, put a bubble into ID/EX

3. Control hazards and branch prediction

Lec 16
In simple wordsAt a branch, the CPU must fetch the next instruction before knowing which way to go. So it guesses. A wrong guess means throwing work away.

Four hardware fixes

FixIdeaCost
StallWait until the branch is decidedEvery branch pays 3
Predict not taken + flushKeep fetching PC + 4; flush if wrong0 if not taken, 3 if taken
Decide earlier (in ID)Move comparison and target adder to IDPenalty 1, but needs forwarding into ID and new stalls
Delay slot (MIPS)The instruction after a branch always runs; compiler fills itFree if filled with useful work

Formula

CPI = 1 + (branch fraction) × (fraction mispredicted) × (penalty)

20% branches, stall always:           1 + 0.20 × 3        = 1.60
20% branches, 60% taken, not-taken:   1 + 0.20 × 0.60 × 3 = 1.36

Static and dynamic prediction

  • Static: one fixed rule. Always not taken, always taken, or BTFN (backward taken, forward not taken; good for loops).
  • 1-bit: predict whatever this branch did last time. In a loop it misses twice: at the exit and again at the next entry.
  • 2-bit saturating counter: needs two misses in a row (from a strong state) to change its mind.
StateMeaningPredictsIf takenIf not taken
00Strong not takenN0100
01Weak not takenN1000
10Weak takenT1101
11Strong takenT1110

For T T T N T T T N: 1-bit (start 1) gets 5/8, 2-bit (start 11) gets 6/8.

Try it: predictor simulator

Type outcomes using T and N.

 

Other ideas you may see

  • Branch Target Buffer (BTB): remembers the target address, so IF can jump at once. Counters are indexed using PC bits.
  • Sorted array mystery: sorting makes data[i] >= 128 predictable (long run of N, then long run of T). Random data is like a coin flip.
  • Real CPUs also use global history, TAGE and perceptron predictors.
  • Spectre: wrong-path work leaves traces in the cache that can leak secrets.

The problem

beq asks two questions: taken? and where?

Target = (PC + 4) + imm × 4
beq at address 40, imm = 7  ->  44 + 28 = 72

In the basic datapath the decision (PCSrc = Branch AND Zero) happens in MEM. By then 3 more instructions have been fetched, so a taken branch costs 3 cycles.

4. CPI, IPC, MIPS and Amdahl's Law

Lec 16 (MIPS formula and example added)
In simple wordsSpeed is judged by total run time. Amdahl says: speeding up only one part helps only as much as that part matters.

Formulas

CPU time = Instruction count × CPI × Clock period
Clock period = 1 / Clock rate
IPC = 1 / CPI
MIPS = Instruction count / (Time × 10⁶) = Clock rate / (CPI × 10⁶)

Example: 10⁹ instructions × 1.36 × 0.5 ns = 0.68 s. At 2 GHz, MIPS = 2000 / 1.36 ≈ 1471.

Why MIPS can mislead: it ignores how much work each instruction does. Adding useless nops can raise MIPS while the program gets slower. (Here "MIPS" is a rating, not the processor design.)

Amdahl's Law

Speedup = 1 / ( (1 - p) + p / s )
p = fraction of ORIGINAL TIME that is improved,  s = how much faster that part gets
Maximum speedup (s -> infinity) = 1 / (1 - p)

Example: p = 0.3, s = 10 → 1 / (0.7 + 0.03) = 1.37×, not 10×.

p50%75%90%95%99%
Maximum speedup2×4×10×20×100×
Exam trapsp is a fraction of run time, not of lines of code.

5. The memory wall, DRAM and locality

Lec 17
In simple wordsThe CPU is very fast and main memory is slow. We keep a small fast memory (cache) nearby, and it works because programs reuse data and use neighbouring data.

The gap

For years processor performance grew about 52% a year, while DRAM latency improved about 7% a year. A trip to DRAM now costs hundreds of cycles.

LevelTypical time
Registerabout 0.25 ns
L1 cacheabout 1 ns
L2 cache3–4 ns
L3 cache10–12 ns
DRAM80–100 ns
SSD50–100 µs
Hard disk5–10 ms

SRAM vs DRAM

SRAM (cache)DRAM (main memory)
One bit uses6 transistors1 transistor + 1 capacitor
SpeedFastSlow
Cost and sizeExpensive, bigCheap, dense
RefreshNot neededNeeded (about every 64 ms), charge leaks

Why DRAM is slow

Cells form a grid of rows and columns. A read has three steps:

  1. Activate (tRCD): copy a whole row into the sense amplifiers (the row buffer).
  2. Column read (CL): pick the wanted bits.
  3. Precharge (tRP): close the row.

Another read from the open row is cheap. A different row is expensive. The full CPU trip also includes checking L1, L2, L3, the on-chip network and the memory controller queue.

CL in time = CL cycles / memory clock

Locality

TypeMeaningExample
Temporal (time)The SAME address will be used again soonloop counter, sum
Spatial (space)NEARBY addresses will be used soonarray a[0], a[1], a[2]

Caches copy a whole block (usually 64 bytes). Reading an int array in order: 16 ints per block gives 1 miss + 15 hits = 93.75%.

C stores 2-D arrays row by row. Going row-wise uses neighbours. Going column-wise jumps far each time and misses much more (0.011 s against 0.20 s in the lecture, about 19×).

AMAT: Average Memory Access Time

AMAT = Hit time + Miss rate × Miss penalty
4 + 0.05 × 200 = 14 cycles      (99% hit rate: 4 + 0.01 × 200 = 6)

6. Cache organisation

Lec 18
In simple wordsThe cache does not search everywhere. Part of the address tells it which row to check. Another part confirms that the right block is there.

Exam hall picture

Rule: bench = last digit of roll number. Student 47 sits on bench 7 (index), with a name card showing 4 (tag). An "occupied" flag is the valid bit.

Address split

| TAG | INDEX | OFFSET |

Offset bits = log2(block size)
Rows (sets) = cache size / (block size × ways)
Index bits  = log2(rows)
Tag bits    = address bits - index - offset

Toy example: address 27 = 01 | 10 | 11 with 4-byte blocks and 4 rows: tag 01, row 10, byte 3.

Each line stores valid bit, dirty bit (write-back only), tag and data. The index is not stored.

Total bits: 32 KB direct-mapped, 64-byte blocks, 32-bit address: tag 17. Each row = 512 + 17 + 1 + 1 = 531 bits; × 512 rows = 271,872 bits.

Try it: address field calculator

Use powers of 2.

Three designs

DesignA block can goTag checksGood and bad
Direct-mappedExactly one slot1Fast, cheap; most conflicts
N-way set-associativeAny of N slots in one setNThe usual compromise
Fully associativeAnywhereAll linesNo conflicts; costly. No index bits

Lookup: pick the set → compare all tags in it → hit if a tag matches and valid = 1.

Trace 0, 4, 0, 4 (4-line toy cache): direct-mapped has 4 misses; 2-way and fully associative have 2.

The 3 Cs of misses

Miss typeWhyCure
Compulsory (cold)First ever access to the blockBigger blocks
CapacityProgram needs more blocks than the cache holdsBigger cache
ConflictToo many blocks want the same setMore ways

Exam recipe: first-time accesses = compulsory. Extra misses in a fully associative cache of the same size = capacity. Any further misses in your cache = conflict.

Exam traps
  • Divide by the number of ways when finding sets.
  • Offset depends on block size, not cache size.

7. Replacement, write policies and multi-level AMAT

Lec 19
In simple wordsThree questions: whom to remove when a set is full, when to update memory after a write, and what the average access costs.

Replacement

PolicyRemovesNote
OPT (Bélády)Block needed furthest in the futureBest possible; cannot be built. Used for comparison

Direct-mapped caches have no choice to make.

Writes

On a write hit (when does memory find out?)

Write-throughWrite-back
UpdatesCache and memory nowCache only; set dirty = 1
Memory writtenEvery storeOnly when a dirty line is removed
Dirty bitNoYes

On a write miss: write-allocate brings the block into the cache, then writes. No-write-allocate writes only to memory. Usual pairs: write-back + allocate; write-through + no-allocate. A write buffer lets the CPU continue while slow writes drain.

Multi-level AMAT

2 levels: HT1 + MR1 × (HT2 + MR2 × P)
3 levels: HT1 + MR1 × [HT2 + MR2 × (HT3 + MR3 × P)]
Solve from the INSIDE out.

Local miss rate = misses at this level / accesses reaching this level. Global = misses at this level / all CPU accesses.

10,000 accesses, 400 miss L1, 100 miss L2: L1 = 4%, L2 local = 25%, L2 global = 1%.

Example: L1 4 cycles, 5% miss; L2 12, 20%; L3 40, 50%; DRAM 200.
L3 part = 40 + 100 = 140 → L2 part = 12 + 28 = 40 → AMAT = 4 + 2 = 6 cycles.

Dirty victims and CPI

Penalty with no write buffer = fetch + (dirty fraction × write-back time)
20 + 0.4 × 20 = 28 ;  AMAT = 1 + 0.05 × 28 = 2.4

CPI = base CPI + (accesses per instruction × miss rate × miss penalty)

8. Virtual memory, page tables and TLB

Lec 20
In simple wordsEach program sees its own private (virtual) addresses. The hardware translates them to real (physical) RAM addresses. The page number changes; the position inside the page does not.

Why we need it

  • Isolation: programs cannot touch each other's memory.
  • No collisions: two programs can use the same virtual address.
  • Bigger address space: parts can stay on disk until needed.

The MMU does the translation. Railway picture: coach name = page number, platform position = frame number, berth = offset.

Pages and page tables

Virtual memory is cut into pages, RAM into frames of the same size (often 4 KB). Each process has its own page table in RAM. The page table base register (CR3 on x86) points to it. Row number = VPN, so the VPN is not stored.

BitMeaning
VValid: page is in RAM
WWritable
UUser programs may access it
AAccessed recently
DDirty: modified

Translate step by step

offset bits = log2(page size)
VPN bits = virtual address bits - offset bits
PFN bits = physical address bits - offset bits
Physical address = PFN joined with the same offset

4 KB pages: last 3 hex digits are the offset
0x2ABC -> VPN 2, offset ABC ; table[2] = 7 -> 0x7ABC

V = 0 gives a page fault. Writing a read-only page gives a protection fault. Frame 0 is a valid frame.

Page table size

entries = 2^(VPN bits) ;  size = entries × entry size
32-bit address, 4 KB page, 4-byte entry: 2^20 × 4 B = 4 MB per process

Most entries are unused. Multi-level page tables create only the parts that are needed, at the cost of more memory reads on a TLB miss.

TLB: a cache for translations

TLB hit: translation is ready. TLB miss: read the page table in RAM.

t = TLB search time, m = memory access time, h = TLB hit ratio
One level:  EAT = h(t + m) + (1 - h)(t + 2m)
k levels:   miss cost = t + (k + 1)m

t=20, m=100, h=0.98:  0.98×120 + 0.02×220 = 122 ns

Page fault steps

  1. Trap to the OS.
  2. Check that the address is legal.
  3. Find a free frame, or choose a victim.
  4. If the victim is dirty, write it to disk.
  5. Load the wanted page.
  6. Update the page tables and remove the old TLB entry.
  7. Restart the instruction.
EAT = (1 - p) × m + p × fault service time     (p = page fault rate)

Thrashing: the system spends most of its time handling page faults.

Exam traps
  • A TLB miss is not the same as a page fault.
  • Do not forget t on the TLB-miss path.

9. The power wall, multicore and MESI

Lec 22 file (the Lecture 21 slide deck)
In simple wordsFaster clocks made chips too hot, so makers added more cores. Each core has its own cache, so they need rules to avoid using old values.

Moore vs Dennard

  • Moore's Law: number of transistors doubles about every 2 years.
  • Dennard scaling: as transistors shrink, power per area stays the same.
  • Dennard broke around 2005: leakage increased and voltage could not drop much below about 1 V.

Power wall

P = C × V² × f        (C capacitance, V voltage, f frequency)

+20% f and +20% V:  1.2² × 1.2 = 1.73  -> 73% more power
Two cores at 0.8 V and 0.8 f:  2 × 0.8³ = 1.02 power, 2 × 0.8 = 1.6 work

The 1.6× work happens only if the program can run in parallel.

Cache coherence problem

Both cores read X = 0. Core 0 writes X = 5 in its own write-back cache. Core 1 still reads its old copy, 0. That is wrong.

  • Write-update: send the new value to other copies.
  • Write-invalidate: tell others to discard their copies. MESI uses this.

Open theory

1. 50 instructions run on a 5-stage pipeline with 6 stalls at 2 GHz. Execution time = ______ ns.

Solution
Cycles = 50 + 4 + 6 = 60. One cycle = 0.5 ns. Time = 30 ns.

2. 75% of run time can be made 3 times faster. Overall speedup = ______.

Solution
1 / (0.25 + 0.75/3) = 1 / 0.5 = 2.

3. 64 KB, 8-way cache, 64-byte blocks, 32-bit address. Tag bits = ______.

Solution
Sets = 65536 / (64×8) = 128. Index 7, offset 6. Tag = 32 − 7 − 6 = 19.

4. L1: 2 cycles, 10% miss. L2: 10 cycles, 20% local miss. Memory: 100 cycles. AMAT = ______ cycles.

Solution
2 + 0.1 × (10 + 0.2×100) = 5.

5. TLB search 10 ns, memory 100 ns, hit ratio 90%, one-level page table, no page faults. EAT = ______ ns.

Solution
0.9×110 + 0.1×210 = 120.
